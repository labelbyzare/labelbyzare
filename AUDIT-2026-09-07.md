# Label by Zare — website audit and fixes, v13

Audit date: 7 September 2026. Website: https://labelbyzare.com. Deliverable: the complete updated website source in this ZIP.

The Instagram CTA on the Support page was present but effectively invisible: its dark text and border matched the black section. This release makes it readable, preserves the premium styling, and normalizes Instagram links to `https://www.instagram.com/thelabelbyzare/`.

The public site was still serving assets from before v12 during this audit. Changes described as fixed below are in v13 source files; they become live when this project is rebuilt and deployed through the existing Netlify project.

## Scope and evidence

- Read-only HTTP checks of 49 public routes, including the homepage, all six collection routes, eight journal articles, ten product pages, support/contact, customer/admin login shells, sitemaps, robots and the product feed. All returned HTTP 200. This confirms those routes responded, not that every possible URL or transaction works.
- Interactive desktop inspection of Support, search, an Emerald Green product page and the guest bag. A search for “abaya under 4000” returned three appropriately priced products. Selecting Medium and adding Emerald Green produced a bag subtotal of PKR 3,860. Related products loaded, and the inspected Support page had no broken loaded images or horizontal overflow at the observed 1,363 CSS-pixel viewport.
- Source review of the shared navigation, mobile rules, cart, wishlist, checkout/contact/newsletter, customer account rendering, login/admin controls, search, product rendering, metadata, schema and Netlify configuration.
- After editing: 34 automated tests passed. The new behavioral tests use isolated DOM, storage and service doubles; they make no real database or email requests. All 45 JavaScript application/build/test files passed syntax checks. A markup audit of 31 rendered pages and 20 source pages found no duplicate IDs, repeated heading texts, missing image alt attributes, missing referenced local script/image/stylesheet files, malformed JSON-LD or incorrect initial drawer/menu hiding attributes. Each checked page had one H1.
- Build completed with `node scripts/build-site.js`. The source retains the approved boutique hero, “MODEST WEAR, Label by Zare.” heading, branded intro, Abaya/Shawl navigation and merchandising, smooth scrolling, SEO improvements and sitemap behavior.

This is a source and public-site audit, not a penetration test or proof of zero defects. New visual changes have not been rendered in a deployed browser. Actual mobile Safari/Chrome, authenticated customer/admin flows, delivery operations and database permissions remain to be verified in the appropriate environment. No live orders, messages, newsletter subscriptions, account deletions or admin changes were performed. Browser extension log errors were excluded from website findings.

## Remaining priorities and recommendations

### P0 — verify before increasing sales volume

**1. Make order creation authoritative on the server.** The frontend currently inserts order items, totals, delivery charges and status directly into `orders`. It refreshes availability, but a browser is not a trusted pricing authority. Database triggers/policies are not included in the supplied source, so their protections could not be established here. Add or verify one authenticated/guest-capable server order endpoint or carefully permissioned database RPC that accepts product IDs, selected variants, quantities and contact fields; reloads prices; calculates shipping; checks stock; assigns status; and saves atomically. Verify database constraints, rate limits and rejection of tampered totals using a staging database.

**2. Verify database grants, row-level security and storage permissions.** Frontend admin allowlisting is not sufficient evidence of database authorization. Test anonymous, customer A, customer B and admin access for `orders`, `profiles`, `addresses`, `cart_items`, `wishlist_items`, `messages`, `newsletter_subscribers`, reviews, product updates and storage buckets. Ensure public tracking returns only the intended limited information and cannot reveal other customers' details. Keep service-role credentials server-side. No unauthorized-record probes were performed. [Supabase RLS guidance](https://supabase.com/docs/guides/database/postgres/row-level-security)

**3. Add server idempotency and unique order identifiers.** Order numbers currently use a six-digit `Math.random()` suffix. Verify a unique constraint, generate identifiers on the server, and bind a stable idempotency key to each checkout attempt. Repeated clicks in one page are guarded; retries, multiple tabs and a lost response after a committed order still need server protection. Test those cases without sending real customer notifications.

### P2 — maintain and improve

- Publish accurate Privacy and Terms pages with the business operator's real practices. Neither page was present in the supplied project. Explain contact/account/order information, analytics, service providers, retention and customer requests using owner-approved content.
- Pin the Supabase browser SDK to a tested exact version or build it into controlled assets; it currently loads the floating `@2` release. Review dependency updates rather than adopting them silently. Consider bundling/self-hosting critical vendor assets after compatibility testing.
- Introduce a Content Security Policy in report-only mode first. Existing inline scripts, handlers, Supabase, fonts and CDNs need a documented allowlist before enforcement. Do not break checkout/auth with an untested restrictive header.
- Enforce admin MFA and verify the requirement in backend authorization, not just the login interface. Keep backups and a tested restoration procedure for products and orders.
- Track real-user performance after deployment. The remote HTTP audit traversed an execution network/proxy and is not a trustworthy visitor TTFB benchmark. No Lighthouse score, 1.5-second load claim or ranking guarantee is made. Check mobile field p75 LCP ≤2.5s, INP ≤200ms and CLS ≤0.1, then examine the slowest page types. Preserve the approved optimized hero and responsive product-image delivery; keep the branded intro short and respect reduced motion. [Google Web Vitals guidance](https://web.dev/articles/vitals)
- Continue accurate product details: fabric, opacity, dimensions, care, available colours and delivery/returns information. Avoid unsupported fabric or performance claims and fabricated reviews. Use real shawl close-ups rather than images that change the actual design.
- Review empty searches and shopping drop-off once analytics is working. Improve synonyms only when they map to actual inventory; preserve strict budgets, sold-out handling and clear no-result states.
- Review keyboard flows after any new overlay or popup is added: visible close control, labelled dialog, focus containment, Escape and focus return. [W3C modal dialog pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)

## SEO and sitemap checks

The live sitemap index and both children responded. `sitemap-pages.xml` contained 21 URLs and `sitemap-products.xml` contained 10, with no duplicates within either file. `robots.txt` referenced `https://labelbyzare.com/sitemap.xml`. Submit that full address in Search Console, or enter `sitemap.xml` when the property URL is already displayed.

In the edited build, the prior v12 fixes remain: page-specific titles, social titles, one H1, non-duplicated heading text, descriptive product/gallery alt text, server-rendered products, canonical collection URLs, PKR offers, no invented ratings, responsive images and public cache/error handling. Existing automated tests cover these cases. Empty collection and search/filter indexing rules remain deliberate; an HTTP 200 utility/login shell is not evidence it should be indexed or that its database is public.

Temporarily unavailable products should stay live with truthful OutOfStock data. For a permanently removed product, redirect only to a genuinely equivalent replacement; otherwise a useful 404/410 is appropriate. Do not redirect every missing item to the homepage. Retain evergreen collection URLs between seasons and update actual inventory.

## Deployment and acceptance

1. Extract the updated ZIP and replace the existing project source with the contents of `LABEL BY ZARE FINAL`. Retain Netlify account configuration and environment variables.
2. Build with `node scripts/build-site.js`. The included Netlify configuration publishes `dist` and deploys `netlify/functions`; use a deployment workflow that builds and includes these functions. Uploading only static HTML will not run the server-rendered pages/sitemaps.
3. Confirm the live Support Instagram button is visible and uses the correct profile. Confirm `20260907-audit1` for changed assets, then check the home intro, mobile navigation, bag Escape behavior and product selection.
4. Run one controlled order in staging or through an owner-approved test process and check the database record, exact total, notification, tracking and account history. This audit did not place that order.
5. Recheck `sitemap.xml`, representative canonical URLs and the Search Console rendered page after deployment. Measure production performance with suitable tools and real-user data.

Reproducible tests:

```sh
node --test tests/*.test.js
node scripts/build-site.js
```
