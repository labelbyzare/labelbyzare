LABEL BY ZARE — v21 OPERATIONS CONTROL SETUP
==============================================

This release adds exactly four operational modules:
1. Activity Log
2. Approval Workflow
3. Returns & Refunds
4. Notifications

IMPORTANT — SUPABASE SETUP
--------------------------
After deploying v21, open Supabase > SQL Editor and run the COMPLETE updated file:

  supabase/admin-dashboard-setup.sql

Run the entire file, not only the v21 section. The script is designed to extend the existing Label by Zare admin setup without deleting your existing products, orders, customers, reviews, discounts, FAQs, guides, or website settings.

APPROVAL WORKFLOW
-----------------
Admin Users now includes "Changes require approval".

- Owner: publishes directly and can review approvals.
- Managing Director: can review approvals only when:
  * Can Apply Changes is enabled,
  * Changes Require Approval is disabled,
  * Approvals permission is enabled.
- Admin: can be configured to publish directly or submit changes for approval.
- Viewer: read-only and cannot submit/publish changes.

When approval mode is enabled for an eligible staff member, supported edits are saved as approval requests instead of being published immediately. An Owner or eligible Managing Director can approve and apply or reject them.

RETURNS & REFUNDS
-----------------
The Returns & Refunds section supports order-linked cases, return/refund type, reason, product condition, requested/refund amount, refund method, tracking reference, workflow status and internal notes. Staff can also start a return directly from an order.

ACTIVITY LOG
------------
The Activity Log records important admin-side changes after the v21 SQL is installed. It records the acting admin, action, section, entity reference, timestamp and changed field names. It intentionally avoids copying full customer/order records into the audit log.

NOTIFICATIONS
-------------
The notification center can surface new orders, reviews, customer messages, return/refund cases, approval requests/decisions and out-of-stock events. Notifications begin accumulating after the v21 SQL migration is installed; historical events are not automatically backfilled.
